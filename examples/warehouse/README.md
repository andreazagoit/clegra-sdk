# Warehouse — a MAP reference app

A small warehouse app ("gestionale di magazzino"): products, stock movements and
customer orders of a shop. It is an ordinary Next.js App Router app with its own
users, to which MAP was added. All companies, people and data are invented.

## Run it locally

```sh
npm run setup   # writes .env.local (generated secrets), creates the tables, seeds the demo data
npm run dev     # http://localhost:3930
```

No Postgres needed locally: without `DATABASE_URL` the app uses PGlite (Postgres in
WebAssembly) in `.data/`. Stop the dev server before running `db:migrate` or `db:seed`
against PGlite (one process at a time). In production `DATABASE_URL` is required; the
app refuses to start on PGlite. Every variable is in `.env.example`.

## How it is built

- **Sign-in**: better-auth, email + password, with the organization plugin: the tenant is
  the session's active organization (`lib/auth.ts`, `lib/session.ts`).
- **Data: plain SQL, on purpose.** No ORM: one `sql(text, params)` and one `transaction(fn)`
  (`lib/db.ts`) over a `pg` Pool or PGlite. The schema is `.sql` files in `db/migrations`;
  better-auth's tables come from its own migration plan, on the same database
  (`npm run db:migrate`). The other reference app (the CRM) uses Drizzle: MAP doesn't care.
- **The app's functions** (`lib/warehouse.ts`): `listProducts`, `registerMovement`,
  `confirmOrder`, … — always scoped by the organization. The pages and server actions call them.
- **The MAP definition** is `lib/modelapp.ts`: one `defineApp` whose handlers call those same
  functions, with the organization the SDK verified (`ctx.installation`). Entities `product`,
  `movement`, `order`; actions `register_movement`, `confirm_order` (always confirmed first),
  `create_order`; fragments, pages (one is the app's own `/embed/stock` board) and an agent.
  `lib/modelapp-auth.ts` maps a verified caller to the person's live role and permissions.
- `npm test` runs the MAP app over its real HTTP path on an in-memory PGlite: tenant isolation,
  the purchase-cost permission, list filters/sort/search/cursor, the actions and fragments.

Serving MCP (`/mcp`, OAuth through better-auth's MCP plugin) is the next step.
